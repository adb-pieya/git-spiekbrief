# Spiekbrief Git en GitHub

## 1. Clone, commit, push en pull

Clone: Je downloadt een project van GitHub naar je eigen computer zodat je eraan kunt werken. Als je cloned wordt het bestand niet automatisch aangepast. Je kan deze projecten die je downloadt dan bekijken en aanpassen omdat je een lokale kopie maakt.

Commit: Je slaat je veranderingen op. Dit kan je vergelijken zoals op de knop "Opslaan" drukken. Elke commit krijgt een beschrijving zodat duidelijk is wat er veranderd werd.

Push: Je zet jouw opgeslagen veranderingen vanuit je computer naar GitHub. Hierdoor kunnen anderen ze ook zien als je ze op publiek zet.

Pull: Hiermee haal je de nieuwste wijzigingen van GitHub naar je lokale repository. Zo blijf je synchroniseren met het werk van andere ontwikkelaars. Dit moet je herhalend doen.

## 2. Een goed commitbericht

een goed commitbericht: contactpagina toegevoegd
een slecht commitbericht: geüpdatet

Waarom is dat een slecht commitbericht?
Het legt niet uit wat er gebeurd is, alleen dat er een aanpassing/update geweest is. Je moet specifieker zijn.

## 3. gitignore

Een gitignore-bestand zegt welke bestanden of mappen git moet negeren.

## 4. Pull

Ik heb een bestand op github.com aangepast en daarna op commit changes gedrukt. Hiermee werden mijn wijzigingen opgeslagen en daarna heb ik mijn wijzigingen naar de main branch gezet en daarna heb ik mijn eigen wijziging gepulld zodat dit daarna ook op mijn vs code staat.

Eerst pull je altijd, hiermee zorg je ervoor dat jou versie volledig mee is met de versies/wijzigingen die andere mensen hebben gedaan. Met commit sla je je wijzigingen op. En daarna pull je zodat de andere mensen ook jouw wijzigingen kunnen zien. Zo werk iedereen synchroon mee met elkaar.

## 5. Terugdraaien

Github bewaart de geschiedenis zodat anderen kunnen zien wat er is gebeurd en wanneer. Dit is handig en goed voor een proper overzicht.
